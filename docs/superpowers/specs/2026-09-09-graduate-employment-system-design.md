# 毕业生就业信息管理系统设计

## 目标

构建一个可在本机运行、面向课程演示的毕业生就业信息管理系统。学生能够维护本人的就业信息；就业办工作人员能够审核、查询并统计就业信息。

## 范围与约束

- 使用 Python 3.10+、Flask、Flask-SQLAlchemy 和 SQLite。
- 采用服务器渲染的 HTML 模板与少量 CSS；不使用前端框架。
- 系统包含两个角色：学生与就业办工作人员。
- 使用本地 SQLite 文件保存数据，启动时可生成固定演示数据。
- 不包含真实身份接入、协议书文件上传、邮件通知、Excel 导出、并发部署或生产级安全加固。

## 架构

应用为单体 Flask 程序。路由层负责页面和表单请求，SQLAlchemy 模型负责数据持久化，模板负责展示。`login_required` 和 `role_required` 装饰器统一控制访问权限。

```
浏览器 → Flask 路由 → SQLAlchemy/SQLite
                 ↓
            Jinja2 模板
```

## 数据模型

### User

| 字段 | 说明 |
| --- | --- |
| id | 主键 |
| username | 登录账号，唯一 |
| password_hash | Werkzeug 生成的密码哈希 |
| role | `student` 或 `staff` |
| graduate_id | 学生对应的毕业生；工作人员为空 |

### Graduate

| 字段 | 说明 |
| --- | --- |
| id | 主键 |
| student_no | 学号，唯一 |
| name | 姓名 |
| major | 专业 |
| class_name | 班级 |
| phone | 联系电话 |

### Employment

每名毕业生最多一条就业记录。

| 字段 | 说明 |
| --- | --- |
| id | 主键 |
| graduate_id | 对应毕业生，唯一 |
| employment_date | 就业时间 |
| employer | 就业单位 |
| employer_type | 单位性质 |
| position | 工作岗位 |
| archive_destination | 档案发往地 |
| remark | 学生备注 |
| status | `pending`、`approved` 或 `rejected` |
| review_comment | 工作人员审核意见 |
| reviewed_at | 审核时间 |

## 用户流程与权限

1. 所有用户从登录页输入账号和密码。
2. 学生登录后进入个人中心，查看个人档案与就业记录；可新增或编辑自己的就业记录。每次保存将状态重置为“待审核”，已审核记录可重新提交。
3. 工作人员登录后进入待审核列表，可按姓名、学号或审核状态检索所有记录；可打开详情并填写审核意见，选择通过或驳回。
4. 工作人员可进入统计页，查看记录总数、待审核数、审核通过数、驳回数，以及按单位性质聚合的通过记录数量。
5. 未登录用户访问业务页面会跳转至登录页；学生访问工作人员页面会得到无权限提示并返回自己的首页。

## 错误处理与校验

- 登录失败显示明确提示，不泄露账户是否存在。
- 学号和登录账号保持唯一；初始化避免重复创建。
- 学生保存就业信息时，就业时间、就业单位、单位性质和档案发往地均为必填项。
- 工作人员审核时必须从通过或驳回中选择一种状态；审核意见为可选。
- 未找到记录返回 404；无权限访问使用闪现消息返回适当首页。

## 验证策略

使用 Flask 测试客户端和临时 SQLite 数据库验证：登录与角色隔离、学生只可更新自己的记录、保存会进入待审核、工作人员审核会更新状态、统计页输出预期汇总。最后运行完整测试集及 Python 编译检查。
